# Filed Under — architecture rules

- Real data is generated by `bun scripts/ingest.ts` into `public/data/` (SEC XBRL statements, filings, iXBRL segments, Form 4, 8-K releases, price + FRED snapshots); never hand-edit those JSON files — rerun the script so every number keeps its SEC accession source.
- Statement building lives in pure modules under `src/lib/financials/` (shared by the ingest script, the app and tests); keep them free of Node/browser APIs.
- Every displayed financial value must carry a `SourceRef` (accession + XBRL concept + period) or a `derived` formula whose parts are SourceRefs, so click-to-source works everywhere.
- Live prices (Yahoo) and macro (FRED) come from server functions in `src/lib/market.functions.ts`; the client falls back to `public/data` snapshots when the live call fails.
- SEC documents are fetched server-side (SEC blocks CORS and requires a User-Agent) through `src/lib/sec.functions.ts`, and rendered in a sandboxed `srcdoc` iframe (no scripts) so the parent can locate and highlight iXBRL facts.
- The signed-in product lives under `src/routes/_authenticated/` (`/app/...`); marketing and auth pages are public top-level routes.
- AI features call the Lovable AI Gateway from server functions only, behind `requireSupabaseAuth`; shared AI outputs are cached in the service-role-only `ai_cache` table.
- tsconfig relaxes `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `noPropertyAccessFromIndexSignature` because the dataset code is index-heavy; keep `strict` on.
- Yahoo throttles shared IPs: every Yahoo call goes through `yahooGet` (alternate hosts, small concurrency pool); quotes and the price job fall back to Nasdaq (stocks/ETFs) and Cboe (VIX) in `src/lib/market-data.server.ts`, then to bundled closes, and news-dependent AI falls back to hosted web search — never let a 429 blank a page.
- Research-agent filing citations use `filing:TICKER:ACCESSION[:DOC]` links with an optional verbatim-phrase link title; the source panel searches that phrase to highlight the passage.
- Layout grids that hold tables or charts must have an explicit column template (`grid-cols-1` at the base breakpoint) and panels carry `min-w-0`, otherwise wide content stretches the page on phones.
- Web research goes through `src/lib/web.server.ts` (Tavily search via `TAVILY_API_KEY`, Firecrawl scrape via `FIRECRAWL_API_KEY`, auto-detecting direct vs gateway keys) and is exposed only through authenticated server functions in `src/lib/web.functions.ts`; web-sourced AI output must list its source URLs.
- Bank-only statement lines are stripped at ingest for companies whose industry isn't a bank/brokerage, so non-banks never show misleading 'net interest income'.
- Fresh data comes from managed scheduled jobs hitting `src/routes/api/public/jobs/$job.ts` (guarded by `authenticateCronRequest`); each run handles a small rotating slice (cursor in `job_state`) to stay within per-invocation limits, writes to Cloud tables, and `src/lib/data.ts` merges those rows over the bundled snapshots.
- Valuation history is point-in-time: each week's multiple uses only fundamentals already filed by that date (`src/lib/financials/valuation.ts`), so charts never look ahead.
- Earnings-call transcripts are found with Tavily (fool.com transcript URLs only, validated against the company before scraping) and read with Firecrawl in `src/lib/transcripts.functions.ts`; parsing and call analytics stay pure in `src/lib/transcripts/`; results go through `cached(..., keep)` so failures are never cached.
- Statement line concepts may be prefix-qualified company extensions (e.g. `cop:...`); SEC companyfacts omits extensions, so ingest reads them from each parsed filing's XBRL and merges them into the facts before building statements.
- Investor-relations documents (SEC 8-K EX-99 exhibits, IR-site PDFs/XLSX/decks found via Firecrawl and Tavily) are stored permanently in the private `ir-documents` bucket with `ir_documents` metadata; PDFs/spreadsheets get an HTML table rendition (`scripts/ir-renditions.ts`) so every IR KPI fact carries a `{t,r,c}` cell locator into the stored copy.
- IR KPI extraction lets the model choose cell coordinates (tables) or number-token ids (slides/images, `src/lib/ir/vision-core.ts`) plus labels only; numbers are re-read from the cell/token. Q4 derivation, flattened-vs-nested merging, per-table scoping, subtotal/double-breakdown inference, partial "selected lines" detection and reconciliation stay pure in `src/lib/ir/kpis.ts`.
- Mass IR AI work (table extraction, vision, label canonicalization) goes through `src/lib/openai.server.ts`, which uses the Lovable AI Gateway by default (`IR_AI_PROVIDER=openai` switches to the owner's `OPENAI_API_KEY`; `claude-*` model ids go to the owner's `ANTHROPIC_API_KEY` via structured outputs) and runs only in bounded single-flight batch scripts (`scripts/lib/runner.ts`: lease in `job_state`, circuit breaker that pauses on auth/quota, optional per-run spend cap, database hiccups retried a bounded number of times); page views never trigger extraction; new files are read by the background runners.
- Every page a vision model reads goes through `scripts/lib/vision-page.ts` (shared by `ir-vision.ts` and the pilot, so pilots measure production): the model must account for every number token (stored, or skipped with a reason), gets one follow-up turn for tokens it leaves out, and Claude pages are rendered/resized to Claude's native image budget; compare models with `scripts/ir-vision-pilot.ts --same=<report.json>` before switching.
- Vision and PDF/XLSX renditions need local tools (pdftoppm, pdftotext, tesseract, ImageMagick), so they run in `scripts/`, never in server functions; page images are stored privately and referenced as `ASSET:path` placeholders that `getIrHtml` swaps for signed URLs.
- Per-company IR series are precomputed (`scripts/ir-build.ts` → `rebuildCompany`) into a JSON payload in storage (`series/TICKER.json`) with stats in `ir_company_series`; the IR page reads that payload instead of raw facts. Rebuild after extraction or label-map changes.
- Scheduled HTTP calls are cancelled after a few seconds: every job stops starting new work once `RUN_BUDGET_MS` (jobs.server.ts) is spent and resumes next run (`ir-docs` tracks done/partial/empty filings in the service-role-only `ir_release_scan`); deep history (`scripts/ir-backfill.ts`) and IR-site discovery (`scripts/ir-site.ts`) run as scripts.
- Bulk pipeline scripts share the app's database: every unit of work waits on `dbGate()` (`scripts/lib/supa.ts`) and `runBatch` sheds workers when round-trips slow, so bulk reading never makes pages time out.
- IR payloads stay fresh without manual steps: `runBatch` rebuilds every company that gained facts every few minutes, `getIrData` rebuilds a missing payload on request, and the IR page polls while files are pending — never put a manual "read now" step between stored data and the page.
- Excel exports share `src/lib/export/xlsx-theme.ts` (palette, number formats, cover); cells hold full values and the $K/$M/$B scale lives in the number format, so formulas stay exact. The IR workbook (`src/lib/export/ir-xlsx.ts`) is built in a web worker because bank-sized exports take seconds to serialise.
- Supply-chain links come from `scripts/supply-chain.ts` reading each company's latest 10-K into `supply_links`; a link is stored only if its quote is found verbatim in the filing (`src/lib/supply/core.ts`), so every edge on the map opens its source sentence.
- Trade ideas come from fixed, point-in-time rules in `src/lib/signals/core.ts`, precomputed by `bun scripts/signals.ts` into `public/data/signals.json` with each rule's historical hit rate vs SPY; rerun after ingest. Paper trades live in the per-user `paper_trades` table.
- The research agent loop lives in `src/lib/research/loop.ts` (server step ⇄ browser tools) and powers the right-side assistant panel (`AssistantPanel`, ⌘J); browser-only tools (navigate_to, get_page_context, run_code in a network-less Web Worker via `src/lib/research/sandbox.ts`) run in `src/lib/research/execute.ts` with an `AgentCtx`.
- Supply-chain exposure, second-order links and shock propagation are pure functions in `src/lib/supply/core.ts`; dollar exposure only comes from stated amounts or stated revenue shares × SEC revenue.
- Earnings reactions, chart patterns and the correlation explorer use pure functions in `src/lib/markets/core.ts`, precomputed by `bun scripts/markets.ts` into `public/data/markets.json` and `returns.json` (3y aligned daily returns) so pages never download every price file; rerun after ingest.
- Supply-chain analyst metrics are pure in `src/lib/supply/core.ts`; the analyst note may only cite stored link ids.
- `scripts/supply-intel.ts` fills `supply_signals` with verbatim-verified quotes; failed stages keep stored rows.
- Public alt data is pulled by `bun scripts/alt-data.ts` into `alt_data` (stable `uid`, upsert-only, every row has `source_url`); contract recipients resolve to parent ids by name prefix, never substring.
- OFR hedge fund data comes from `bun scripts/hedge-funds.ts` into `public/data/hedge-funds.json`, values as published with source URLs; rerun, never hand-edit.
- Hedge/auction analytics: `src/lib/hedge/core.ts`; auctions: `scripts/treasury-auctions.ts`.
- AI briefs/notes may only cite browser-assembled fact ids.
- Supply-chain country/region/concentration/freshness/basket analytics are pure in `src/lib/supply/analytics.ts`; web cross-checks keep only sentences naming both companies.
- Promises keep only verbatim-verified quotes (`vetPromises`); alerts are pure diffs in `src/lib/alerts/core.ts` over sourced rows.
- Analyst estimates: `scripts/estimates.ts` fills `analyst_estimates` (Node fetch is throttled by the provider); `getEstimates` reads it and refreshes live after 6h. Pure fixes in `src/lib/estimates/core.ts`.
