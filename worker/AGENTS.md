# Render services

- The IR deep build loop runs on the always-on Render worker `filedunder-ir-worker` (this folder's Dockerfile), with progress kept in the database so restarts resume. It reads companies one per lane (lanes and reader counts sized from the cgroup memory limit), holds a 3-minute lease tagged with its host so a restarted container takes over at once, and never counts out-of-memory kills against a company — because fixed sizes and a long lease turned every crash into a 15-minute stall.
- Office engine: private repo `nevaubi/filedunder-office-engine`, Render service `filedunder-office-engine` (not shared with JuneDesk); it trusts only tokens from this app's `/api/public/office/jwks`.
- Office files: `office_files` rows (ULID ids, owner-only RLS) + private `office-files` bucket under `<uid>/`; engine tokens are minted only by `getEngineToken` (`src/lib/office/files.functions.ts`) with the `OFFICE_ENGINE_JWT_PRIVATE_KEY` secret, because the engine trusts nothing else.
- Writer saves the real `.docx` (built in the browser by `src/lib/office/writer-docx.ts`) plus a `<id>.writer.json` copy of the exact editor state; imported Word files are read with mammoth when no state copy exists yet.
- OfficeAI is the shared research agent (`runAgent`) plus per-editor tools from `src/lib/office/agent-tools.ts` (sent by `agentStep` when `office` is set) executed in the browser by each editor's executor (e.g. `writer-agent.ts`); add editor capabilities there, not a separate agent.
