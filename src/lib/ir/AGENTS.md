# IR data rules

- Opt-in vision escalation re-reads incomplete/rejected/OCR pages with the stronger model and stores that page's model provenance; failed page reads stop document replacement, and targeted reruns scope claims and resets to their document ids to protect unrelated companies.

- Explicit Ling reads use streamed server-only OpenRouter connector replies; comparison scripts use capped token batches, bounded retries and local checkpoints without writing facts, so interrupted or incomplete answers cannot change production data.

- IR KPI extraction lets the model choose cell coordinates (tables) or number-token ids (slides/images, `src/lib/ir/vision-core.ts`) plus labels only; numbers are re-read from the cell/token. Q4 derivation, flattened-vs-nested merging, per-table scoping, subtotal/double-breakdown inference, partial "selected lines" detection and reconciliation stay pure in `src/lib/ir/kpis.ts`.
- Mass IR AI work (table extraction, vision, label canonicalization) goes through `src/lib/openai.server.ts`, which uses the Lovable AI Gateway by default (`IR_AI_PROVIDER=openai` switches to the owner's `OPENAI_API_KEY`; `claude-*` model ids go to the owner's `ANTHROPIC_API_KEY` via structured outputs; `google/*` ids use the gateway chat-completions surface, the only one Gemini supports) and runs only in bounded single-flight batch scripts (`scripts/lib/runner.ts`: lease in `job_state`, circuit breaker that pauses on auth/quota, optional per-run spend cap, database hiccups retried a bounded number of times); page views never trigger extraction; new files are read by the background runners.
- Every page a vision model reads goes through `scripts/lib/vision-page.ts` (shared by `ir-vision.ts` and the pilot, so pilots measure production): the model must account for every number token (stored, or skipped with a reason), gets one follow-up turn for tokens it leaves out, and Claude pages are rendered/resized to Claude's native image budget; compare models with `scripts/ir-vision-pilot.ts --same=<report.json>` before switching.
- Vision and PDF/XLSX renditions need local tools (pdftoppm, pdftotext, tesseract, ImageMagick), so they run in `scripts/`, never in server functions; page images are stored privately and referenced as `ASSET:path` placeholders that `getIrHtml` swaps for signed URLs.
- Per-company IR series are precomputed (`scripts/ir-build.ts` → `rebuildCompany`) into a JSON payload in storage (`series/TICKER.json`) with stats in `ir_company_series`; the IR page reads that payload instead of raw facts. Rebuild after extraction or label-map changes.
- IR page data comes from two sources: the partner FiledUnder corpus (read-only REST via `src/lib/ir/external.server.ts`, converted purely in `src/lib/ir/external.ts`, doc ids `x:<id>`) and own `ir_company_series` payloads from deep builds; `getIrData` shows whichever has more series, so a deep build becomes visible without a manual step and never put a manual "read now" step between stored data and the page.
- The IR tab's financial map (company → zone → breakdown → line) is built purely in `src/lib/ir/map.ts` from the same IR payload as the tables, so every bar opens the stored source cell; tone rules live there with tests.
- `scripts/ir-docling.ts` prepares a company's files before reading: dates/accessions only from evidence (`doc-meta.ts`), PDFs as a page-by-page hybrid of Docling tables and the pdftotext layout grid (`rendition.ts`, Docling wins a page only when it keeps ≥90% of its numbers), scanned pages left to ir-vision and decks marked `skipped:slides`, so no number is read twice.
- Fast table readers use small prompt parts (`--chunk=16000`), the checklist and escalation in `extract-quality.ts`; `readChunk` is shared by `ir-extract.ts` and `ir-model-pilot.ts` so a pilot measures production.
- `scripts/ir-deep.ts` runs deep builds company by company (dates → tables → slides → retry → rebuild → report, Docling conversion in the background, converted files in a final pass) and skips companies that already have figures unless listed in `--continue`; `scripts/ir-deep-loop.ts` drives it nonstop (resume unfinished companies, then largest no-figure companies; mirror resume; waits and probes when credits run out, single-flight lease `ir-deep-loop`); spend is a gateway-credit ledger in `job_state` (`ir-deep-ledger`, reset per loop run); `--budget` is optional (absent = uncapped, owner's standing choice) and caps readers via `--max-credits` only when given; a company counts as finished only when its report (`ops/ir-deep/T.json` in private storage) reaches stage `final`; per-model credit rates live in `GATEWAY_CREDITS` (`openai.server.ts`), fitted from gateway logs.
- Period grids are pure in `periods.ts`: quarterly columns hold only fiscal quarter-ends (or columns with flows); balances at other month-ends live in the monthly view (`mo` on a series, `months` on the payload; `periodGrids`/`cellsFor` also split older payloads). `kpis.ts` fills Q2/Q3 from year-to-date columns (6M − Q1, 9M − 6M) before deriving Q4. Key metrics, biggest moves and the current-first breakdown order are pure in `highlights.ts`.
- Duplicate or complementary IR tables are merged after the build by the pure `tidyPayload` (`tidy.ts`, run in `buildPayload` and on load for older/partner payloads): lines merge only when their names agree (table name included) and their values never conflict, another split of the same total never joins, every cell keeps its own source, and totals whose parts changed are re-checked; bump `TIDY_VERSION` when the pass changes so stored payloads are re-tidied on load. Segment names come only from segment tables that tie out; lines naming one segment and one measure become one row of a "<measure> by segment" table closed by the consolidated line (a copy when that line also closes another table), and a period missing one of its parts is left unchecked rather than flagged.
- Balances, averages and prices never get flow formulas (year = four quarters, Q4 = year − quarters): `stockKind` in `stock.ts` decides, shared by the build and the tidy pass (which drops such cells from older payloads), because summed quarter-end balances showed 4× annual figures.
- The text reader (`prose-core.ts` pure, `prose.server.ts`, `scripts/ir-prose.ts`) reads figures stated in HTML releases' sentences after their tables: the model points at numbered tokens, values are re-read from the token, vague ("more than"), forecast and boilerplate figures are dropped, figures a same-day table already prints are skipped, facts are stored with method `text` and locator `{q: sentence}` so the viewer finds the sentence (`quotedBlock`) and marks the figure; claims carry their time in `prose_at` so only abandoned claims are re-queued, and a document where every part was unusable fails instead of counting as read.
- The owner's OpenAI key is a second-opinion lane for public IR documents only (shared traffic may be used by OpenAI, so user files and chats never go through it): `openai-lane.server.ts` reserves tokens atomically in `openai_allowance` within the free daily caps (`openai-allowance.ts`) and returns null when spent or failing, so readers carry on with the built-in models alone. Text reads cross-check every part; disagreements are settled by the dates the document prints (`preferPrinted`), then the large-model arbiter, else dropped; the second reader's solo finds are never stored (pilot showed shifted labels). `scripts/ir-prose-verify.ts` re-checks older text reads with what new reads leave of the day. Table parts and vision pages also get a parallel second read on the lane (`second-read.ts`, pure): same-cell/token figures dated differently are dropped, primary solo finds stay, the lane's solo finds are never stored, and its reading replaces a primary answer only when that answer was unusable (`IR_OPENAI_TABLES=0` / `IR_OPENAI_VISION=0` turn it off).

- OpenRouter free models (`free-lane.ts` pure, `free-lane.server.ts`, via the existing OpenRouter connection) are a third opinion only: they settle reader disputes first and the OpenAI arbiter is the fallback (`IR_ARBITER_ORDER=openai-first` reverses it), choosing a or b or neither and never adding a figure; one account within its free daily cap (`free_model_usage`), failing models rest an hour, 429s rest the lane, never key or account rotation.

- Worker reading on the owner's own OpenAI key: `IR_FREE_ONLY=1` reads within the free daily allowance and, with `IR_OPENAI_PAID=1`, continues on the paid key with the same model once it is spent (`paidStructured`, tokens logged as `paid_mini`/`paid_large` in `openai_allowance`); neither path ever spends Lovable AI credits, because the owner pays OpenAI directly for worker reads.

- IR scale: `parseNumber` never reads a cell holding two numbers; `factsFromModel` takes the money scale from the table's own evidence (full-unit cells, printed scale words) and `screenRows` (`scale-check.ts`) marks contradicted figures in `locator.suspect` instead of storing them as confident values.

- Stored figures the documents contradict are held by `suspect.ts` at the end of `tidyPayload` (`series.held`): never plotted, summed, checked, compared or exported; shown as a flag with the reason and click-to-source. Never correct a value by multiplying or dividing it.

- Conflicting vintages are ordered by `orderVintages` in `kpis.ts` (suspect last, newest filing, undated at period end + 45 days, document kind, documents printing it, method, ids); the shown cell keeps the other value as `alt` (restated or conflict).

- IR tidy folds lines only on evidence: identical printed values (never "close"), the line that stays keeps its own cells and sources, and a cousin fold must make its total add up without breaking any period. Checks are recomputed from the parts shown; a period that can't be read off the page is unchecked, never "adds up". Passes look lines up by key or value (no pairwise scans); the page runs the tidy in `ir-page.worker.ts`.

- Period heads (`periods.ts` `fiscalLabel`/`uniqueHeads`): a fiscal year number only for December year-ends; otherwise "FY ending <month>" and "Q<n>" over the month, per era, off-grid periods by month, never two identical heads.

- Rule 7 of `suspect.ts`: a figure whose other printing, or a same-named line of the same table, is 1,000× or 1,000,000× it (within 0.5%, the slip being the side farther from the company's usual quarter figures) is held, with the same document's other figures of the line and its parts. An IR page shown before the company's statements arrive is checked when they do (`checkLate` in `unpack.ts`, through `checkLateIrPage`), gaining holds and flags without moving any figure.

- Files of another company stored under a covered ticker are refused by `source-guard.ts` from the reviewed list in `source-guard-list.ts` (ticker, host, optional path, owner, evidence): the reader runner marks them `skipped:other-company`, docling, the series build, the page (document list, stored payload cells, partner conversion) and the IR-site collectors skip them. The list names known-wrong files only; it certifies nothing else. Add an entry only with the titles or site that prove it.

- SEC check (`sec-check.ts`): a figure of a consolidated table is always compared; only a line that is a part of the company (`partOf`: a table named by segment, subsidiary, geography, product and the like, or a line nested under one that is not a consolidated standard line) may skip the comparison, and another line that agrees excuses only such parts. A compared consolidated figure that equals the filing's figure for another quarter up to 740 days away is held. "Later filing only" (`later`) needs a gap of at most `RECAST_LIMIT` (15%) and no agreeing line of the period; otherwise the figure is flagged and the reason says why. The build keeps same-named lines of two tables apart when their levels differ by `LEVEL_SPLIT` (2.2×) or more (`levelSplits` in `kpis.ts`); payloads built before that are not repaired at read time.

- TTM (`ttm.ts`): lines or cells printed as TTM, LTM or trailing twelve months, twelve-month cells in quarter columns and year columns closing off the 10-K year-end leave the columns at tidy time and in the SEC check; the count is shown (`data-section="IR trailing twelve months"` and in each table caption). A held cell whose other printing has the same digits 1,000× or 1,000,000× is replaced by that printing if it passes every rule. Rule 7 needs the same digits to the printed precision. A segment-table total with at most one part is compared with the filing as a part.

- IR statements (`statements.ts`, pure, tests on real rows in `fixtures/statements/`): a section is one printed table of the newest document that prints it (doc index and `locator.t`), rows in printed row order, older copies of the table joined on by the lines they share (`STITCH_SHARE`), a line stored under two identities shown as one row only on evidence (the same printed row, or the same name, unit and total in another document with no figure in conflict), children indented by the stored hierarchy, totals bold only where the section prints their parts. The build stores where each line is printed in its newest two documents (`series.at`) and the printed title, scale line, headings and spacer rows of section tables (`payload.tables`, `table-captions.ts`, read from the same stored text the table reader used); without them sections fall back to the stored table name. Figures show in the printed scale (`printedDiv` from value ÷ printed text), never rescaled beyond that. A payload built before `at` and `tables` existed still lays out, with fewer joined rows and stored names.

- IR statement rules (round 7): a section holds exactly the rows its anchor table prints, in printed order, under the names printed there (`rowLabel`); another copy of the table adds a line only as history of such a row (same printed row, or same name, unit and total at the same printed scale with no figure in conflict), its other lines go to "<title>: lines only other copies print" in the collapsed more group; a figure printed at another scale never joins or fills a row. A row shows its own table's printing (`series.at` fourth element: differing figures and printed name; `BUILD_FORMAT` 2, `needsRebuild`). Page order (`arrange`): the newest supplement's tables (else the release's) in its order; tables only other documents of the same release print (within `RELEASE_DAYS`), marked by source; sections of at most `FRAGMENT_LINES` lines folded into one "Smaller tables" section; tables of older documents in a collapsed "More tables" group. A label-map drop never removes a printed table figure (`applyLabelMap`). Tie marks sit in a fixed gutter; first paint lays out one section.
- Stale payloads: every rebuild writes `stats.build` (= `BUILD_FORMAT`) beside the payload, and the IR loop's `ir-rebuild` step (`scripts/ir-rebuild-stale.ts`, rules in `scripts/lib/ir-rebuild-stale.ts`) rebuilds the companies whose stats lack it, banks first then by rank, one at a time, at most 20 companies or 15 min a pass, only with no reading run and also while the reader route is closed on credit; it calls no model. A failed company waits a day, three failures leave it for review (lane state `ops/ir-rebuild-stale.json`, `job_runs` job `ir-rebuild-stale`). On by default; `IR_REBUILD_STALE=0` turns it off. Bump `BUILD_FORMAT` when stored payloads must be rewritten.

## IR statement assembly rules (round 8)

- Hierarchy (`statement-tree.ts`, `shapeRows`): a stored parent counts only where the section prints it in the same block as the child (no heading between them, except a total printed below sub-blocks with no other total between, as JPM's "Total deposits" under "U.S. offices" and "Non-U.S. offices"); the nearest printing below wins, else the nearest above. Rows that lost their total come back from the total's own block: beside parts stored under it they are siblings (up to the first subtotal above them, whose block they belong to); with none stored they are its parts only when their figures add up to it in at least one period and differ in none, nearest rows first. Depth is the chain of such parents, a row is bold only when it closes printed parts here, a heading sits one level above the outermost line it heads, and `up` (the parent row's index) is what checks compare (`blockParts`). Reason: Apple's category lines were indented under "Products" three headings up and JPM's noninterest revenue lines sat beside their own subtotal.
- Headings (`assembleStatements`): a printed heading heads a line only when nothing but headings, spacer bands and wrapped-label rows are printed between them; a heading over rows the reader did not keep is not drawn (it would head the wrong lines, as Oracle's growth-rate headings over unread percentage rows did).
- Names (`sameName`, `nameCore`): two lines carry the same printed name when they are equal up to case, footnote marks ("(a)", "(1)", "*") and a closing colon, or when one is the other under its block's name (the parent total without "Total", or the stored table name), as Broadcom's older releases stored "Stock-based compensation expense: cost of revenue". Every join on names (the same printed row of another copy, the same name under the same total) uses it, so older quarters join the row instead of being listed apart.
- Bases (`basisSplits`, `basisOf` in `kpis.ts`): a line one document prints under two stated bases (reported or GAAP against comparable, adjusted, organic, constant currency, managed and the like, read from the table name) is two series even in a period where the figures agree, and a section holding both heads each block with its stored table name where the printed heading was not kept. Reason: Coca-Cola's comparable segment revenue lost the four segments whose comparable figure equals the reported one.
- Merged copies keep their printings (`mergeFlattened`): a flattened line folded into its nested twin hands over its printed positions, so the table that printed it still shows the row (GE's segment tables lost their "Revenue" row to the summary's segment line).
- Rows of several column groups (`nameTwins`): lines printed on one row of the anchor table sit in printed column order, and lines there under one name are told apart by what they measure ("EMEA: revenue", "EMEA: operating income"), else by their table name (`twin` on the row); never two rows under one name.
- Matrix tables printed twice in one release (`drafts`): a second table of the main document joins a section when it gives the same lines for other periods only (Intel's segment matrix for this quarter and last year's), and a second printing of a line in one table that gives only periods its first printing does not is that row's history, not a row of its own (Coca-Cola's prior-year block). Reason: one printed table, one section, one row per printed row.
- Printed headings keep the document's case (`headText`): only a heading shouted in capitals is put in sentence case ("Client and Gaming Segment" stays, "NONINTEREST EXPENSE" reads "Noninterest expense"); a heading sits at the level of the outermost total whose parts are all printed under it, else one level above its first line. A row whose stored name repeats the heading over it ("Cloud Memory Business Unit: Revenue") reads without it (`under`).
- Captions (`table-captions.ts`): a title may be the table's own first row ("Quarterly Financial Results" over Micron's "FQ4-26" heads; "quarterly" alone is not a period head) or the label cell of the period-heads row (Texas Instruments' "Consolidated Statements of Income"); the company's legal name "... and subsidiaries", a bullet or a sentence with figures, and "trailing 12 months" are never titles.
- A part's stored parent across a heading counts when no other total closes a block between them, a total stored under that same parent not counting (AMD's "Data Center Segment" over "Total Client and Gaming" to "Total net revenue").
- Scale of a row (`ownScale`, `rowCells`): a row printed in a table takes that table's printed scale from its own cells and own printings (`series.at` figures); a figure the line shows from another table at another scale never fills it, and the table's own printing of a period replaces it; the section's scale line follows the same printings. Reason: Netflix's thousands reconciliation showed three quarters from its millions regional table.
- A clause ending a paragraph ("... are below.") is never a table title (`titleLike`, `tableTitle`).
- Main document (`arrange`): a document stored without a filing date belongs to the release when it prints the newest period; a document whose tables a supplement copy of the same release is stitched onto ranks as the supplement (`copies` on a section). Reason: Citigroup's EX-99.2 supplement is stored as "other" and its investor-site PDF copy carries no filing date, so the page opened on the release's services table.
- Printed layout (build format 3, `PayloadTable.rows` read optionally as `PrintedLayout`): a row takes the name its anchor table prints at its position (`name`, before any stored or composed name), its bold and rule marks (`bold`, `rule` on the row, also `bold` on headings) for the renderer, and its printed indent level where the table prints two or more levels among the section's lines (`printedLevels`), unless the table indents totals past their parts (JPM), where the stored levels stay. A document whose title calls it a supplement (`docs[].hint`) ranks as one. Sibling parts are not adopted when the stored parts already add up to the total.
- One printed row, one measure (`sameRows`): lines sharing a printed position join only in the same unit and with the same metric or name (a slide's cost and revenue lines at one height stay apart). Lines of several bases on one printed row are named by basis and measure ("Subscription gross profit: non-GAAP margin") instead of being headed by basis; a printed row name names its lines only when they are one line under one name and it is not a date (tables with dates down the side).
- Captions: "The following table summarizes ..." and similar introductions are not titles; a title naming results, statements, highlights or a reconciliation may carry a period ("Third Quarter 2026 GAAP and Non-GAAP Results"); Title Case is lowered word by word except words with capitals of their own ("Non-GAAP").
- Section kinds (`sector-order.ts`): `sectorOf` reads the sector from the sector and industry fields the app has (SEC industry text); `sectionKind` classifies a section by its printed title (never renaming it) into income statement, balance sheet, average balances and yields, net interest margin, segment results, credit quality, capital, per-share and ratios, underwriting, production and prices, product, geography, revenue, costs, cash flows, reconciliations, highlights; `assembleStatements(p, { sector, industry })` sets `kind` and the tab filter (`filter`, the `DIMENSIONS` values) on each section; `jumpGroups` orders the jump list by the sector's statements while the page keeps the company's order; `missingStatements` lists the sector's expected statements no section (or heading inside one) prints, and `missingHeadlines` a bank's headline measures (ROE, ROTCE, CET1, NIM, efficiency or overhead ratio, book and tangible book value per share) no line prints. Reason: one grouping for the filters, the jump list and the note on what a company's documents leave out.
- Lines only older documents print (`old` on the row): a line of an older copy of the table (filed more than `RELEASE_DAYS` before the anchor) that joins no printed row closes the section under the heading "Printed only in earlier periods", never among the rows the table prints now and never at the top; lines another document of the same release prints stay in "<title>: lines only other copies print" in the more group. Reason: the newest document's order wins and history stays reachable beside its table.
- Signs in names (`signWords` in `kpis.ts`): a sign printed straight before a figure is a word of the series key ("plus 100 bps", "minus 100 bps"), so JPM's +100 and -100 bps earnings-at-risk rows are two series; label-map keys (`rawKey`) are left as stored so existing maps still apply.
