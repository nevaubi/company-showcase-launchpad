# IR data rules

- Opt-in vision escalation re-reads incomplete/rejected/OCR pages with the stronger model and stores that page's model provenance; failed page reads stop document replacement, and targeted reruns scope claims and resets to their document ids to protect unrelated companies.

- Explicit Ling reads use streamed server-only OpenRouter connector replies; comparison scripts use capped token batches, bounded retries and local checkpoints without writing facts, so interrupted or incomplete answers cannot change production data.

- IR KPI extraction lets the model choose cell coordinates (tables) or number-token ids (slides/images, `src/lib/ir/vision-core.ts`) plus labels only; numbers are re-read from the cell/token. Q4 derivation, flattened-vs-nested merging, per-table scoping, subtotal/double-breakdown inference, partial "selected lines" detection and reconciliation stay pure in `src/lib/ir/kpis.ts`.
- Mass IR AI work (table extraction, vision, label canonicalization) goes through `src/lib/openai.server.ts`, which uses the Lovable AI Gateway by default (`IR_AI_PROVIDER=openai` switches to the owner's `OPENAI_API_KEY`; `claude-*` model ids go to the owner's `ANTHROPIC_API_KEY` via structured outputs; `google/*` ids use the gateway chat-completions surface, the only one Gemini supports) and runs only in bounded single-flight batch scripts (`scripts/lib/runner.ts`: lease in `job_state`, circuit breaker that pauses on auth/quota, optional per-run spend cap, database hiccups retried a bounded number of times); page views never trigger extraction; new files are read by the background runners.
- Every page a vision model reads goes through `scripts/lib/vision-page.ts` (shared by `ir-vision.ts` and the pilot, so pilots measure production): the model must account for every number token (stored, or skipped with a reason), gets one follow-up turn for tokens it leaves out, and Claude pages are rendered/resized to Claude's native image budget; compare models with `scripts/ir-vision-pilot.ts --same=<report.json>` before switching.
- Vision and PDF/XLSX renditions need local tools (pdftoppm, pdftotext, tesseract, ImageMagick), so they run in `scripts/`, never in server functions; page images are stored privately and referenced as `ASSET:path` placeholders that `getIrHtml` swaps for signed URLs.
- Per-company IR series are precomputed (`scripts/ir-build.ts` → `rebuildCompany`) into a JSON payload in storage (`series/TICKER.json`) with stats in `ir_company_series`; the IR page reads that payload instead of raw facts. Rebuild after extraction or label-map changes.
- IR page data comes from two sources: the partner Filed Under corpus (read-only REST via `src/lib/ir/external.server.ts`, converted purely in `src/lib/ir/external.ts`, doc ids `x:<id>`) and own `ir_company_series` payloads from deep builds; `getIrData` shows whichever has more series, so a deep build becomes visible without a manual step and never put a manual "read now" step between stored data and the page.
- The IR tab's financial map (company → zone → breakdown → line) is built purely in `src/lib/ir/map.ts` from the same IR payload as the tables, so every bar opens the stored source cell; tone rules live there with tests.
- `scripts/ir-docling.ts` prepares a company's files before reading: dates/accessions only from evidence (`doc-meta.ts`), PDFs as a page-by-page hybrid of Docling tables and the pdftotext layout grid (`rendition.ts`, Docling wins a page only when it keeps ≥90% of its numbers), scanned pages left to ir-vision and decks marked `skipped:slides`, so no number is read twice.
- Fast table readers use small prompt parts (`--chunk=16000`), the checklist and escalation in `extract-quality.ts`; `readChunk` is shared by `ir-extract.ts` and `ir-model-pilot.ts` so a pilot measures production.
- `scripts/ir-deep.ts` runs deep builds company by company (dates → tables → slides → retry → rebuild → report, Docling conversion in the background, converted files in a final pass) and skips companies that already have figures unless listed in `--continue`; `scripts/ir-deep-loop.ts` drives it nonstop (resume unfinished companies, then largest no-figure companies; mirror resume; waits and probes when credits run out, single-flight lease `ir-deep-loop`); spend is a gateway-credit ledger in `job_state` (`ir-deep-ledger`, reset per loop run); `--budget` is optional (absent = uncapped, owner's standing choice) and caps readers via `--max-credits` only when given; a company counts as finished only when its report (`ops/ir-deep/T.json` in private storage) reaches stage `final`; per-model credit rates live in `GATEWAY_CREDITS` (`openai.server.ts`), fitted from gateway logs.
