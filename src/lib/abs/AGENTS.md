# ABS-EE: asset-level data of asset-backed securities

- Source: Form ABS-EE and ABS-EE/A on EDGAR, exhibit EX-102 (the asset data file, XML). Two callers share one reader (`filing.ts`): the scheduled job `abs-ee` (`src/lib/jobs/abs-ee.server.ts`) stores one waiting filing per run for the CIKs in `watch.ts`, or lists one of them when none waits; `scripts/abs-ee.ts` lists (`discover`), stores oldest first in bounded batches (`load`), re-reads stored filings from SEC and compares (`verify`) and prints totals (`status`) for any CIK and range, with no time or size limit. History, and any file too large for a scheduled run, go through the script.
- The scheduled run reports failure only when the database or the code fails. A filing it cannot read is recorded on the filing (`status`, `status_detail`), an attempt is counted before the work and given back when SEC throttles or is down, and a filing it cannot finish in three attempts is left for the script; least-tried filings go first, so one stuck filing never holds up the rest. It is not in the freshness page's expected-cadence list (`SOURCES`): add it there only once its schedule exists and has run cleanly, or the watchdog reports it silent.
- Evidence kept with every stored filing: accession, form, filing and acceptance time, the cover period and the issuer, depositor and sponsor CIKs from the EDGAR header, the document list, and the size and SHA-256 of the asset file's bytes as SEC served them (`abs_filings`, `abs_documents`, `abs_loads`). A figure can be traced to the file, and the file checked against its hash.
- Values are stored as filed. A column holds the number, date or yes/no the text spells; text that does not spell one leaves the column empty and is kept word for word in `unparsed`; a field with no column is kept word for word in `extra`. Nothing is rescaled or corrected: some files write a rate as 0.0343 and others as 3.89, so a rate figure carries the unit `as_filed` until a per-file scale is established from the file itself.
- Two periods exist and are not the same thing: the cover period of the filing (EDGAR header, `abs_filings.period_start/period_end`) and the reporting period each record states (`period_begin/period_end` on the record). A file made for an offering is dated to a determination date that can lie after its filing date. Keep both; say which one a figure uses.
- Identity. A deal is the issuing entity: the header's filer that is not the depositor, keyed by its CIK as ten digits (`dealOf`); a filing whose only filer is the depositor is keyed by depositor CIK and file number; a header that establishes neither is not stored. `asset_number` is the filer's own number: unique within one file in the files seen, not stable across a deal's files (the offering file and the monthly files may number differently, a loan split into notes appears as 3, 3A, 3B, a property of a multi-property loan as 26-001 or 9.01). Rows are keyed by position in the file (`rec`). `classifyRecords` decides with the whole file in view: a row numbered after a loan in the same file that states no balance or payment status of its own is a property of that loan, even when it carries an amount (an offering file puts the loan amount allocated to each property on these rows, and counting them as loans counts that money twice); a numbered row with a balance of its own is a loan (a note of a split loan); a row no loan number fits stays untied, never guessed. What the file-wide look could not settle is kept with the load (`abs_loads.counts.notes`).
- The header's asset class is the filer's label: a header may list several, and one has been seen wrong ("Auto loans" on a commercial mortgage trust). It is stored as filed on the filing; what a deal is (`abs_deals.family`) comes from the namespace of its asset files, and a file of another family is refused for that deal rather than changing it.
- No company attribution. The tables hold SEC CIKs for issuer, depositor and sponsor and names as filed. Saying that a pool belongs to, or is a risk of, a covered company needs its own evidence (legal role at the time, retained interest) and is not derived from a name.
- Revisions are kept. An amendment is its own filing with its own rows. Among the loaded filings of one deal and one cover period, the one SEC accepted last is `is_current`; the others point at it (`superseded_by`). Nothing is overwritten.
- Storing is all or nothing per filing: rows go under a new load (`abs_begin_load`, `abs_put_rows`) and become the filing's data only when `abs_commit_load` has counted them against what the reader parsed. A run can be stopped anywhere; the next run starts a cut-off filing over. A filing already stored from the same bytes by the same reader version is not stored again. Readers use the `*_live` views, which show only committed loads of loaded filings.
- The importer holds no SQL. Everything it does to the database is one of the service-role functions of migration 0067, called through `scripts/lib/abs-store.ts`. Do not write `abs_*` tables from anywhere else. `abs_check()` lists the store's invariants; every count must be zero after every run.
- Figures (`abs_pool_metrics`) are defined in `metrics.ts`; `PARSER` is bumped whenever a reader or a definition changes what gets stored, and `abs_loads.parser` records which version stored each filing. Every figure carries `n` and `n_missing`. Sums and weighted averages use exact decimal arithmetic (`decimal.ts`), so the same file gives the same figure on every run.
- Read today: commercial mortgage files (`cmbs`). Auto loan and auto lease filings can be listed, and are marked `skipped` with the reason "unsupported" until their reader exists (their files are 30 to 220 MB and are aggregated in one streaming pass, not stored row by row).
- The asset file reader (`xml.ts`) refuses a document it does not understand (deeper nesting, text beside elements, another root) instead of reading half of it. It was checked record for record against an independent parser on real files.
- Tests: pure modules beside them; the store's rules on a real PostgreSQL in `src/test/abs-store.db.test.ts` (set `ABS_DB_URL` to a scratch database on this machine). To prove a change end to end, apply the migration to a scratch Postgres and run the importer with `ABS_DB_URL` set; `ABS_FAULT=<begin|put|commit>:<n>` kills the process at that point of the n-th filing.
