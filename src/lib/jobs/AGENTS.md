# Scheduled refresh jobs
- Empty Form 4 receipts use `job_state` keys `form4-seen:<accession>` rather than fake trade rows, so successful derivative-only reads cannot starve the parsing queue or pollute financial data.
- Refresh jobs prune `job_runs` after 14 days except `vendor-backfill` rows, because vendor lifetime spending ceilings depend on the full ledger.
- Estimates use `estimates-new` for missing-coverage rotation and `estimates-backoff` for a persistent source cooldown, so scheduled failures do not hammer the provider or skip an unattempted ticker.
- FINRA refresh uses stored SPY session dates and advances its date receipt only after a whole-session upsert, so holidays never block catch-up and interrupted writes remain retryable.
- Release failures retain attempts/errors in `job_state` (`ir-release-retry:<accession>`), which alone decides the six-hour back-off and giving up after three attempts (`releaseDue` in `ir.server.ts`). `ir_release_scan.status` accepts only done, partial and empty (check constraint), so a failed attempt writes nothing there: writing `retry`/`error` was refused by the database, left no row, and one filing with a 403 image blocked the queue for a day. Only successful stores count as complete. A test double for a table must refuse what the table's constraints refuse.
- New filings are found market-wide by `sec-discover` (EDGAR current feed + daily master index, covered CIKs) and resolved through `syncCompany`, so latency never depends on the per-company walk's rotation.
- Options: 403/429 is a block, not 'no options' (SPY probe); a block holds the slice and backs off in `options-backoff`. The tail offset is `options-tail`, moved by the tail names the night reached.
- Form 4s are read by one reader (`storeForm4`): the `sec` walk takes 2 per company per visit, and the worker's `form4-repair` pass reads every other Form 4 in `sec_filings`, day by day (`form4-repair` cursor, `form4-fail:` tries, give up after 3).
- Estimates: a per-ticker failure goes to `estimates-fail:<T>` (3 tries, 6 h apart, then 7 days off) and never sets the provider cooldown. Only provider-wide errors set `estimates-backoff`, whose reason names the ticker that is fetched last next run.
- Watchdog episodes are held for a recovery time after they clear (`cleared …`, 6 h; heartbeat 1 h); a recurrence inside the hold is the same episode. Mark an episode sent only when the digest has an `email_log` row (`queueEmailRecorded`).
- Freshness remedies ask once per staleness episode (`remedy:<key>` reason `episode:<newest>`). Supply intel takes a one-off `supply-intel-request` that `intelDue` honours only for a clean marker with no recorded run behind its last advance. Never write `supply-intel-weekly` from outside the intel step.
- `fake-supabase` caps responses at 1,000 rows and refuses `.in()` lists over 500: page and chunk real queries.
